# 新脚本使用说明（loginfix 版）

> 脚本文件：`finishedProduct/bilibili_live_multi_py36_obs27_loginfix.py`
> 适用人群：已经用过 `bilibili_live_multi_py36_obs27.py`，现在换成修复版的人
> 修复内容与原理见：[登录问题修复说明.md](登录问题修复说明.md)

---

## 一、它是什么

同一个 OBS 直播脚本的**修复版**，文件名多了 `_loginfix` 后缀。功能、界面、账号数据全部和原版一致，只有登录链路和账号列表容错做了改动。

原脚本一行未改，两份可以并存，随时切换。

---

## 二、安装前的准备

| 项目 | 要求 |
|---|---|
| OBS Studio | 30+（Windows 7 用户用 26.1.1+） |
| Python | 3.9–3.12，或 3.6（仅 Windows 7） |
| 已有环境 | 已经在用原版 `bilibili_live_multi_py36_obs27.py`（说明 Python 环境已配好） |

如果还没配过 Python 环境，先按仓库 README 的「配置方法」把原版跑通，再换这个脚本。

---

## 三、放到哪里

**关键点：新脚本必须和原脚本放在同一个目录。** 脚本会把账号数据存在自己旁边的 `bilibili-live` 文件夹里，放错目录会读不到已有账号（表现为列表为空）。

### macOS

```
/Applications/OBS.app/Contents/PlugIns/frontend-tools.plugin/Contents/Resources/scripts/
```

把 `bilibili_live_multi_py36_obs27_loginfix.py` 复制进这个目录，与 `bilibili_live_multi_py36_obs27.py` 并列。

> 如果复制时提示 `Operation not permitted`，这是 macOS 的「App 管理」保护，不是文件损坏。两种处理：
> 1. 系统设置 → 隐私与安全性 → App 管理 → 允许「访达 / 终端」，再复制；
> 2. 或把**两个脚本一起**放到用户目录（如 `~/Documents/OBS-Scripts/`），在 OBS 里用 `+` 号分别加载——只要两者同目录，账号数据仍然共用。

### Windows

```
C:\Program Files\obs-studio\data\obs-plugins\frontend-tools\scripts\
```

同样与原脚本并列摆放。

## 四、在 OBS 里加载

1. OBS 主界面 → 顶部菜单 **工具 → 脚本**
2. 看「已加载脚本」列表，找到原来那个 `bilibili_live_multi_py36_obs27.py`
   - **把它前面的勾去掉**（不要点 `−` 删除，留着以后回滚）
3. 点左下角 **`+`** → 选中 `bilibili_live_multi_py36_obs27_loginfix.py`
4. 右侧属性面板会出现脚本界面；下方「脚本描述」应显示：

   ```
   bilibili_live_multi_py36_obs27_loginfix（登录修复版）
   ```

   看到这行说明选对了文件。

> ⚠️ **不要同时勾选新旧两个脚本。** 两者共用同一份 `config.json`，同时运行会互相覆盖账号状态。
>
> 如果属性面板一片空白，点一下面板里的 **「启动脚本」** 按钮，它会重新生成控件。

## 五、第一次添加账号（重点）

属性面板里从上到下是几个折叠分组：**账号 / 直播间 / 直播预约 / 弹幕 / 脚本设置**。登录相关操作全在「账号」组里。

里面的按钮有：`二维码添加账户`、`显示二维码图片`、`更新账号列表`、`登录账号`、`登出账号`、`删除账户`、`备份账户`、`恢复账户`，以及一个「用户」下拉框。

### 步骤

**第 1 步**：展开「账号」分组。
此时「用户」下拉框显示 `添加或选择一个账号登录`，上方状态文字是 `未登录，请登录后点击【更新账号列表】`。

> 注意：没有账号时，`登录账号` 按钮是**隐藏**的，这是正常设计——先要有账号才能登录。

**第 2 步**：点 **`二维码添加账户`**。
脚本会做三件事：
- 在「脚本日志」框里打印一个**字符画二维码**
- 同时生成二维码图片（暂存在内存）
- 开始每秒查询一次扫码状态

**第 3 步**：点 **`显示二维码图片`**，屏幕上会弹出一个二维码窗口。

> 如果弹窗没出现，直接用第 2 步日志里的字符画二维码扫也可以（等宽字体下能扫）。
> 若字符画错乱、扫不出来，再点一次 `二维码添加账户`，它会重新出图。

**第 4 步**：用手机 App 扫码，并在手机上点「确认登录」。

**第 5 步**：等日志出现这几行（`<...>` 是你的真实信息，不会显示在本文档里）：

```
ticket 换到的字段: ['SESSDATA', 'bili_jct', 'DedeUserID', 'DedeUserID__ckMd5', 'sid']
登录凭据采集结果: ['SESSDATA', 'bili_jct', 'DedeUserID', 'DedeUserID__ckMd5', 'sid']
添加用户成功: uid=<你的UID>
```

看到 `登录凭据采集结果` 里有 `SESSDATA`，就说明凭据已经拿到了。脚本会清掉内存里的二维码，**但弹出图片的窗口不会自动关闭，需要你手动关掉**。

**第 6 步**：点 **`更新账号列表`**。
「用户」下拉框这时应该出现你的昵称，上方状态文字变成 `<昵称> 已登录`。

到这里就完成了。后续开播、改标题、推流码等功能和原版完全一样。

## 六、日常操作

| 想做的事 | 怎么做 |
|---|---|
| **切换账号** | 「用户」下拉框选目标账号 → 点 `登录账号`。脚本会把它设为默认账号 |
| **再添加一个账号** | 直接点 `二维码添加账户` 扫新号，成功后点 `更新账号列表` |
| **临时不用某个账号** | 点 `登出账号`，会清除「默认账号」标记，账号本身仍保留在列表里 |
| **彻底删掉某个账号** | 下拉框选中它 → 点 `删除账户`。若删的是当前默认账号，脚本会先清掉默认标记再删 |
| **刷新登录状态** | 点 `更新账号列表`。修复版会先清掉查询缓存再重新校验，所以网络恢复后再点一次就能刷出昵称，不会一直卡在数字。只有服务端明确回「凭据失效」的账号才会被移除 |
| **备份 / 恢复账号** | 这两个按钮目前是**空实现**（上游还没做完），点了不会有反应。要备份请直接复制第七节的 `config.json` |

## 七、账号数据存在哪

脚本所在目录下的 `bilibili-live` 文件夹：

```
<脚本所在目录>/bilibili-live/
├── config.json        ← 账号信息（含登录凭据，注意保密）
├── commonData.json    ← 分区、分区列表等常用数据缓存
├── cache/             ← 接口缓存
├── img/               ← 封面等图片缓存
├── danmu/  danmu.html ← 弹幕相关资源
├── log/               ← 脚本自己的日志
└── temp/              ← 临时文件
```

macOS 默认安装位置下就是：

```
/Applications/OBS.app/Contents/PlugIns/frontend-tools.plugin/Contents/Resources/scripts/bilibili-live/config.json
```

**备份**：把整个 `bilibili-live` 文件夹复制走即可。
**换机迁移**：把文件夹放到新机器同位置，登录状态直接可用（凭据过期则需重新扫码）。

> ⚠️ `config.json` 里是**可直接登录你账号的凭据**，等同于密码。不要发给别人、不要传到公开仓库、不要贴到聊天记录里。

## 八、怎么确认跑的是修复版

打开 **帮助 → 日志文件 → 查看当前日志**，加载脚本时应当出现：

```
============================================================
B站直播脚本【登录修复版 loginfix】已生效
  修复: Set-Cookie 取凭据 / ticket 换 cookie / UA 升级 / cookie 双重编码 / 账号列表容错
============================================================
```

没有这段横幅 = 加载的还是旧文件，或者 OBS 没重新载入脚本（在脚本列表里点「重新载入脚本」）。

## 九、常见问题

**Q：点「二维码添加账户」后日志没有任何反应？**

先确认脚本是否加载成功（看第八节的横幅）。若横幅在但仍无反应，检查网络能否访问外网，再看日志里有没有 `申请二维码` 相关报错。

**Q：扫码后日志显示「登录成功」，但 `更新账号列表` 之后还是空的？**

这正是修复版要解决的问题。如果仍然出现，说明加载的还是旧脚本——按第八节核对横幅。

**Q：「用户」下拉框里显示的是数字而不是昵称？**

说明这次查询昵称失败了（网络或接口临时问题），脚本用 uid 兜底显示，账号本身可用。稍后点 `更新账号列表` 即可重试——修复版会清缓存后重新查询，不会一直停在这个状态。

**Q：账号用着用着突然从列表里消失了？**

修复版只在服务端明确返回「凭据失效」时才移除账号。若仍被移除，通常是登录确实过期了，重新扫码添加即可。

**Q：能不能只放新脚本、把旧脚本删掉？**

可以。但建议先保留旧文件一段时间，确认新版稳定后再删，方便回滚。

**Q：换回旧脚本，账号会丢吗？**

不会。账号数据在 `bilibili-live/config.json`，与加载哪个脚本文件无关。

## 十、停用与回滚

1. OBS → 工具 → 脚本
2. 取消勾选 `bilibili_live_multi_py36_obs27_loginfix.py`
3. 重新勾选 `bilibili_live_multi_py36_obs27.py`
4. 点一下「重新载入脚本」

账号数据不受影响。
